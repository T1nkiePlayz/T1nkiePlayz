## 👋 About me

I'm a student from **Western Australia** who turns ideas into working software. I like building things from scratch and understanding every layer of them: game servers, launchers, tools, websites and games.

Lately that has meant a lot of **Rust**, and a lot of tools that are **local-first**: your data stays on your machine, and the app keeps working when the internet doesn't.

- 🦀 **Rust** for the serious stuff: servers, launchers and game projects
- 🎮 **Game dev**: gameplay systems, tooling and pixel art in Aseprite
- 🏗️ **Architecture**: keeping bigger projects maintainable (and tested)
- 🐧 **Linux & self-hosting**: Hyprland, Docker, homelab experiments
- 📚 **Teaching**: free handbooks for learning Rust and Java

> 💬 *Breaks things → fixes them → blames Linux.*

<table>

    <td valign="top">
      <h3><a href="https://github.com/T1nkiePlayz/Moss">Moss</a> <sub>· <em>Game servers that keep growing, quietly.</em></sub></h3>
      <p>A fast, <strong>local-first controller for Minecraft Java servers</strong> on Linux and macOS: one small Rust binary with an embedded web panel, full mod support and compatibility checks, and servers that survive everything except you pulling the plug.</p>
      <ul>
        <li>🔁 <strong>Servers outlive the controller</strong>: kill or upgrade Moss mid-game and the server, console and players are untouched</li>
        <li>🧩 <strong>Compatibility checks on real jars</strong> for Paper, Fabric, Quilt, Forge, NeoForge and Velocity, plus Modrinth &amp; CurseForge</li>
        <li>💾 <strong>Backups you can trust</strong>: checksummed, verifiable, with restore previews and S3-compatible remote destinations</li>
        <li>⬆️ <strong>Version upgrade assistant</strong> with per-mod verdicts, rollback and undo for every change</li>
        <li>⚡ A ~34&nbsp;KB (gzipped) Svelte UI, no Docker required, containers optional</li>
      </ul>
